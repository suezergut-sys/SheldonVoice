# SheldonVoice

SheldonVoice — клиент Android 10+ для голосового общения с одним Telegram-ботом, например с уже настроенным OpenClaw. Вы выбираете бота, записываете голосовое, подтверждаете отправку и читаете ответ в том же окне. Сообщения идут от вашего обычного Telegram-аккаунта и остаются в его диалоге с ботом.

Приложение не поднимает собственный сервер, не настраивает OpenClaw и не требует доступа к VPS. Связь с Telegram обеспечивает TDLib через MTProto. Токен бота, Telegram Bot API, реклама и аналитика не используются. Если бот ещё не настроен или не умеет обрабатывать голосовые, сам клиент эту возможность ему не добавит.

## Обновление 0.1.1 поверх установленной версии

Для обновления нужен APK с тем же сертификатом подписи, что и установленная версия. Откройте совместимый APK и выберите **Обновить**, не удаляя приложение и не очищая его данные. Тогда локальная сессия и выбранный бот сохранятся. При сборке на другом компьютере отладочный ключ обычно будет другим: Android не разрешит установить такой APK поверх прежнего. В этом репозитории публикуются исходники; APK и ключи подписи в Git не хранятся.

## Как устроен проект

Проект написан на Kotlin. Интерфейс построен на Jetpack Compose, состояние экрана — на `ViewModel` и `StateFlow`, асинхронные операции — на корутинах. Приложение состоит из трёх Gradle-модулей:

| Модуль | Что делает |
| --- | --- |
| [`app`](app) | `MainActivity` показывает авторизацию, настройку бота, ленту сообщений и кнопки записи. `VoiceViewModel` связывает экран, жизненный цикл, разрешение на микрофон и операции с Telegram. `AndroidVoiceRecorder` управляет системным `MediaRecorder`. |
| [`core`](core) | Не зависит от Android. Содержит интерфейсы `VoiceRecorder` и `TelegramRepository`, контроллер записи `VoiceController`, модели авторизации и доставки, объединение истории в `MessageTimeline` и JVM-тесты. |
| [`telegram`](telegram) | `TdTelegramRepository` загружает `libtdjni.so`, использует Java API TDLib, превращает callback-ответы в suspend-вызовы и публикует состояние Telegram через `StateFlow`. `SecureVault` хранит локальные настройки и ключ базы. |

Приложение создаёт один репозиторий Telegram на процесс. Команды пользователя идут из Compose через `VoiceViewModel` к контроллеру записи или репозиторию. В обратном направлении события TDLib проходят через очередь в репозиторий и обновляют состояние диалога, которое читает Compose.

### Что происходит после запуска

1. TDLib открывает локальную базу. Если параметры Telegram API не сохранены, приложение предлагает их ввести. Дальнейшие экраны зависят от запроса TDLib: номер телефона, код или пароль двухэтапной аутентификации. Сохранённая действующая сессия позволяет пройти сразу в состояние `READY`.
2. При выборе бота приложение ищет публичный username и проверяет, что это личный диалог с аккаунтом типа `UserTypeBot`. Сохраняются username и `chat_id`; операции с сообщениями выполняются только для выбранного диалога.
3. После подключения репозиторий открывает чат и запрашивает до пяти страниц истории, не более 50 сообщений за запрос. История и события TDLib объединяются по идентификатору сообщения. В ленте остаётся до 250 последних сообщений, отсортированных по времени и идентификатору. Изменения текста и окончательные удаления обновляют ленту.
4. Список Compose закреплён у конца диалога. При открытии или новом сообщении показывается последнее сообщение; добавление старой истории не меняет его позицию. Голосовые в ленте отображаются подписью с длительностью, прочие вложения — текстовой заглушкой.

### Как запись превращается в сообщение

1. Запись возможна только при активном экране, разрешённом микрофоне, действующей сессии и выбранном боте. При открытии с домашнего экрана после настройки запись запускается автоматически, но отправляется только по кнопке.
2. `MediaRecorder` пишет монофонический Opus в контейнер Ogg: 48 кГц, 32 кбит/с. Таймер использует монотонные часы Android. `VoiceController` управляет состояниями `IDLE → RECORDING → SENDING → IDLE`, блокирует двойную отправку и переводит ошибку в `ERROR`. Короткую запись меньше секунды он не отправит.
3. При отправке репозиторий делает приватную копию файла в `outbox` и передаёт её TDLib как `InputMessageVoiceNote`. Если TDLib приняла сообщение, исходная запись удаляется. Если запрос отклонён до принятия, контроллер может сохранить черновик до явного повтора или сброса; после завершения процесса черновик не восстанавливается.
4. У сообщения свой статус: **в очереди** (`PENDING`), **отправлено** (`SENT`) или **ошибка отправки** (`FAILED`). Отметка об отправке относится к доставке Telegram, а не к тому, обработал ли бот запись. `MessageTimeline` учитывает, что подтверждение TDLib может прийти раньше ответа на запрос: поздний статус ожидания не возвращает уже отправленное сообщение в очередь. Если TDLib разрешает повтор, приложение передаёт идентификатор сообщения в `ResendMessages`.

## Подключение к Telegram

1. Откройте https://my.telegram.org и войдите по своему номеру.
2. Откройте **API development tools**, зарегистрируйте приложение (платформа Android).
3. Сохраните `api_id` и `api_hash`. Это данные Telegram API приложения, **не токен бота**.
4. При первом запуске SheldonVoice введите их на телефоне. Они не встраиваются в APK, не нужны для сборки и не попадают в Git.
5. Введите телефон в международном формате, код из Telegram/SMS и пароль 2FA, если запрошен. Способ доставки кода определяет Telegram; сторонним клиентам SMS может быть недоступна.
6. Введите точный `@username` своего OpenClaw-бота. Клиент проверяет, что это именно бот, и сохраняет `chat_id`. При первом диалоге нажмите «Отправить /start».

Официальная инструкция: https://core.telegram.org/api/obtaining_api_id.

## Сборка и установка

Нужны Android Studio с JDK 21, Android SDK Platform 36 и доступ к Google Maven/Maven Central. Gradle Wrapper 8.14.3 включён. Откройте эту папку отдельным проектом Android Studio, выберите Gradle JDK 21, дождитесь Sync. Путь к SDK задайте через `ANDROID_HOME` или локальный (игнорируемый Git) `local.properties`.

Windows PowerShell:

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

На Linux/macOS: `./gradlew :core:test :app:lintDebug :app:assembleDebug`. Debug APK подписан отладочным ключом, подходит для личной установки. Для релиза нужен собственный signing key вне репозитория. APK: `app/build/outputs/apk/debug/app-debug.apk`.

Если Windows JVM-тесты из папки с кириллицей завершаются `ClassNotFoundException` (кодировка Java argument file), задайте каталог результатов без кириллицы: `-PbuildRoot=C:/Temp/claw-voice-build`. Тогда APK будет в `C:/Temp/claw-voice-build/app/outputs/apk/debug/app-debug.apk`, отчёты — в соответствующих подпапках `core/reports` и `app/reports`. Исходники остаются на месте. Альтернатива — разместить весь проект в `C:/dev/voice-telegram-client`.

Для установки без USB скопируйте APK на телефон, откройте и разрешите установку из выбранного источника. Включать USB debugging нужно только для установки через adb.

## Использование и разрешения

После настройки бота нажмите «Разрешить микрофон». Экран заранее объясняет автоматическую запись. Если авторизация, бот и разрешение уже настроены, открытие с домашнего экрана запускает видимую запись с таймером. «Отменить» удаляет запись; «Отправить» завершает её и передаёт TDLib. Минимум 1 секунда, максимум 10 минут (по достижении лимита запись отменяется).

При сворачивании, блокировке экрана и переходе в другое приложение текущая запись отменяется. Автоматический запуск повторяется при новом открытии с launcher; простое возвращение из фона не возобновляет микрофон. При повороте экрана запись также отменяется. Для новой записи после отправки есть кнопка.

Запрашивается только runtime-разрешение `RECORD_AUDIO`; `INTERNET` — обычное разрешение манифеста. Нет background microphone service и фоновой записи. Уведомления в MVP отсутствуют, поэтому `POST_NOTIFICATIONS` не запрашивается, в том числе на Android 13/14+. После восстановления сети TDLib продолжает принятую очередь. Failed-сообщения повторяются по их Telegram message_id, а не как новая запись.

«Обновить» и повторный запуск загружают последние сообщения; ответы бота и редактирование текста приходят через TDLib updates. Автоматически отправлять запись после перезапуска приложение не будет.

## Безопасность

- Сессия и сообщения TDLib находятся в приватном `noBackupFilesDir`; база TDLib шифруется случайным 256-битным ключом.
- Ключ базы, api_id/api_hash и настройки бота хранятся в AES-GCM blob; ключ шифрования находится в Android Keystore.
- Код и 2FA-пароль существуют только в памяти во время ввода, не сохраняются.
- Backup/перенос данных отключены; скриншоты и превью recent apps защищены `FLAG_SECURE`. Логи TDLib отключены.
- Ogg-записи и копии для исходящей очереди находятся в приватном хранилище; **сами аудиофайлы не имеют дополнительного прикладного шифрования**. Применяется защита хранилища Android. Принятые TDLib копии сохраняются для повтора (см. ограничения).
- Номер телефона, код и пароль вводятся на устройстве. Секреты не нужны для сборки: не добавляйте их в `BuildConfig`, Gradle, `.env`, документацию, задачи GitHub или отчёты. Gitignore исключает распространённые локальные конфиги, базы, ключи, записи и сборки.
- Голосовые и текст проходят через Telegram. Бот получает отправленное сообщение и может обрабатывать его на своей стороне. Это обычный диалог с ботом, без режима секретных чатов.
- Для отзыва доступа: Telegram → Настройки → Устройства → завершить сессию SheldonVoice; затем очистить данные Android-приложения. При потере Keystore после восстановления очистите данные и войдите снова.

## Проверки

Для регрессии прокрутки добавлены 4 Android Compose-теста `ChatMessagesTest`. Соберите `:app:assembleDebugAndroidTest`, установите основной и тестовый APK в эмулятор/телефон, затем выполните `adb shell am instrument -w -r dev.openclaw.voice.test/androidx.test.runner.AndroidJUnitRunner`. Обычная команда запуска — `:app:connectedDebugAndroidTest`; прямой запуск через adb также позволяет обойти сбой инфраструктурного UTP runner на Windows. Результаты проверки версии 0.1.1 — в [BUILD_VERIFICATION.md](BUILD_VERIFICATION.md).

`core:test` проверяет разрешение на микрофон, повторный старт, монотонный таймер, уход в фон, короткую запись, ошибки start/stop, двойное нажатие отправки, удержание Sending до принятия, сохранение черновика при ошибке и явный повтор. `lintDebug` проверяет Android API и манифест; `assembleDebug` — Kotlin, Compose и упаковку нативных библиотек.

Ручная приёмка на телефоне: отказ/выдача/отзыв разрешения, вход с 2FA, выбор чужого не-bot username, запись→отмена, запись→отправка→ответ OpenClaw, авиарежим→отправка→возврат сети, force-stop→повторный запуск→история, блокировка экрана во время записи. Потребуются ваши credentials и аккаунт; эти сценарии нельзя подтвердить только сборкой APK.
